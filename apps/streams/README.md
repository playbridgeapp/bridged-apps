# Bridged Streams

Svelte web client for Stremio-compatible catalog addons and browser-compatible Nuvio stream plugins. Sign in with a Stremio or a Nuvio account (one at a time). Browse and play on the website; cast to PlayBridge when available.

## Run

From `bridged-apps/`:

```bash
pnpm install
pnpm dev:streams
```

Open `http://127.0.0.1:5182`. Install at least one Stremio-compatible addon with a catalog and metadata resource to browse titles. Add configured manifest URLs directly. Home shows featured titles, Continue Watching, Browse by Addon, and catalog rows. Search has a search bar and a Discover feed with Type, Catalog, and Genre dropdowns; compatible catalogs load more titles as you scroll. Catalogs that require an option use the addon's first listed option by default, such as the current year in Cinemeta's New rows. Nuvio plugin repositories add stream sources to those titles; they do not supply catalogs.

## Search

Search runs on Submit/Enter or selecting a recent query. Each searchable catalog runs concurrently with an eight-second deadline. Usable previews publish in 32 ms batches while a quiet **Still searching…** status remains for pending catalogs; failures/timeouts are distinct from a completed no-match and can be retried.

New cards append in publication order. Catalogs ready in one batch use configured catalog/item order, and the earliest configured catalog has priority for duplicate fields. Progressive publication preserves existing keyed cards. A fully successful refresh removes obsolete previews so the view matches the fresh result set. While a card is pressed or keyboard-focused, only the prefix needed to keep that card in place is temporarily retained; stale cards below it are removed. The section height is reserved during that interaction so removing tail rows cannot clamp the viewport and move the tap target. The remaining stale prefix and reserved space are released 150 ms after interaction ends, allowing the click to finish. No stale-preview notice or extra submission is needed.

A memory-only cache keeps complete successful queries for five minutes, with LRU limits of twelve queries, 1,200 total previews and one million serialized characters. Oversized queries are not cached. Exact repeats/recent queries show cached previews immediately and refresh in the background; repeated Submit while a query is already running joins the same requests. Partial/failed/timed-out refreshes never replace or renew a completed snapshot. Account/profile/PIN identity changes cancel requests, clear the cache and submitted route. Source-configuration changes (including background manifest refreshes) cancel outdated requests and drop old-configuration cache entries while preserving the submitted query and current cards. A 400 ms debounce coalesces those changes into an automatic search against the latest targets, with no skeleton flash when previews are already available. Saved profile selection is initialized before asynchronous restore; routine profile readiness is not a privacy change, and deep links waiting for restore retain their query intent. Locked Nuvio sources are excluded. Clear/new queries cancel their previous requests, while ordinary tab return retains the current query without refetching. Existing recent-query history remains separate; result previews are never persisted.

## Navigation and shared links

Cached addons and available catalogs open while account and manifest refreshes run in the background. The player keeps its source screen and unfinished provider requests alive, so starting a ready source or returning to its list does not repeat the lookups. Sources restored later are added to the open stream list.

Pushed screens use URL routes with browser Back and Forward support. Hash routes work on the static Cloudflare deployment and the local server without rewrite configuration:

- Legacy `/#/search?q=Avengers`, `/#/library`, and `/#/settings` links open the tab once, then replace the URL with `/#/`
- `/#/settings/accounts`, `/#/settings/addons`, and `/#/settings/integrations` for Settings panels
- `/#/movie/tt1234567` for a movie's details
- `/#/series/tt1234567?season=2` for a selected season
- `/#/series/tt1234567/streams?video=tt1234567%3A2%3A3&season=2&episode=3` for episode streams
- `/#/catalog/ADDON_ID/movie/CATALOG_ID` for one catalog

Links resolve metadata and streams using the recipient's enabled addons. They do not install addons or contain account credentials or resolved stream URLs. Season and episode choices survive refreshes. Back returns from the player to streams, from streams to details (or the originating Continue Watching page), and from details to the originating catalog or tab. Scroll positions and loaded catalog pages are retained during navigation in the current page session. The player also has a route; reloading or sharing it opens stream selection so a fresh source can be chosen.

Home, Search, Library, and Settings switch immediately, without page or grid entrance animations, and work like a native app's bottom tabs: tabs share the base `/#/` URL and never add history entries. Back from any tab leaves Streams (in PlayBridge, to the dashboard). Reload opens Home. Selecting a tab while pushed screens are open returns to the base history entry first, so Back does not walk through the discarded screens. Back from a pushed screen restores its originating tab; Settings panels return to Settings. Legacy tab links open once and normalize to the base URL without adding history. Inactive tabs unmount, so their posters are not kept in the page, but each tab keeps its place for this page session: its scroll position and, on Home, each row's horizontal position and revealed cards. Tapping the current tab scrolls it to the top. Places are forgotten when the account or profile changes. The dock starts expanded on each page load, becomes compact after 5.5 seconds, and stays compact across scrolling and tab switches until the page is reloaded. Search keeps the typed draft, submitted query, and last results in memory, so returning to Search does not fetch them again. Search submissions do not change the URL; an inbound legacy search link can seed the query once. Detail, stream, and catalog screens still restore their scroll positions. Catalog, detail and stream navigation use one 280 ms directional screen transition with full-width slides and underlying-screen parallax, without staggered content entrances. Browser history traversal (including iOS swipe-back) and reduced motion skip that transition. The dock and player retain their own presentation. Touch layouts omit desktop hover overlays, and poster images decode asynchronously.

Refresh restores a recently opened title's name and artwork from a session cache (up to 24 titles for six hours), then loads fresh metadata. Uncached title links show a loading skeleton rather than a raw media ID. Playback actions remain disabled while details and account sources restore.

## Bridged Apps on Android

The site serves `/.well-known/playbridge-app.json`, which opts it into PlayBridge's Bridged Apps launcher. Open the deployed HTTPS site, or a local development server at a private LAN address such as `http://192.168.1.23:5182`, in PlayBridge's Android browser and choose **Add Bridged App** from the menu. Its tile then appears on the PlayBridge dashboard. Tapping the tile opens the site without browser chrome; Android Back returns to the dashboard after the site's own navigation history. Long press the tile to remove it. Installation and casting permission are separate.

Production builds register a service worker that caches the public app shell (the page and the versioned files it loads first) and other versioned app files (JavaScript, CSS, fonts, images, and WebAssembly). Page loads use the latest online shell, falling back to the complete cached shell if the network fails or takes more than 1.5 seconds, and work offline as far as the cached shell and cached Home allow; with nothing cached, an offline page replaces the browser error. The shell is stored only together with every file it needs, so a cached page never references a missing file. A slow network fetch continues updating the cache after the fallback opens. Open pages remember updated entry assets and reload on their next return from hidden to visible, preserving the hash route, at most once per version. Visibility returns also check for deployments, at most once a minute. An update found within three seconds of returning reloads immediately if there has been no interaction; later updates or updates found after interaction wait for another return. Addon, account, stream, and media requests are excluded, and nothing private is cached. Vite development builds do not register the worker. In the PlayBridge iOS app, WebKit doesn't run service workers for apps like PlayBridge (it requires app-bound domains or a browser entitlement), so there Streams behaves as before: it opens normally online, but a cold start without a network shows the browser's error. `pnpm test:e2e:streams-sw` tests the worker against a production build.

Sports Streams and some other addons mark direct HTTP sources `notWebReady` even when the playlist and segments permit browser requests. These sources appear with **Try in browser** and **Cast** actions. Browser playback can still fail if the media host blocks it. Stream lookup errors now appear beside the source list.

## Signing in

Without an account, Home offers **Continue with Nuvio**, **Continue with Stremio**, or adding an addon URL yourself. Streams uses one account at a time: signing in to the other provider (**Settings → Accounts and profiles → Switch to …**) signs the current one out only after the new sign-in succeeds, after first trying to deliver its queued watching changes. A browser that still has both accounts from an earlier version is asked which one to keep.

## Stremio account sync

Open **Settings → Accounts and profiles → Sign in to Stremio** and sign in with your Stremio email and password, or use an existing auth key for an account linked to another sign-in provider. Your password is sent directly to Stremio over HTTPS and is not stored. The auth key stays in this browser's site storage until you disconnect or clear site data.

The app imports your Stremio addons, library, and Continue Watching progress on sign-in and every 10 minutes. **Sync now** refreshes them immediately. Install an addon with **Stremio account** selected, remove an account addon, or change a Stremio library entry to write it back. Addons saved directly in Bridged Streams remain local. Nuvio plugin repositories and the TMDB key are separate from Stremio's addon collection.

Linked TV casts report movie and episode watch position to Stremio when PlayBridge sends playback state updates. On older PlayBridge versions without linked casting, movies use a direct cast without progress callbacks. Browser playback reports progress for both. Catalog and stream requests still depend on each addon's browser CORS support.

## Nuvio account sync

Open **Settings → Accounts and profiles → Sign in to Nuvio** and sign in with your Nuvio Cloud email and password. The app uses [Nuvio's published public client key](https://github.com/NuvioMedia/self-host/blob/main/.env.example). For a self-hosted account, select **Server → Change**, enter its backend URL, and load its public key from `/.well-known/nuvio` or enter the key printed by `./nuvio credentials`. Never enter a service-role or secret key. The password is not stored; the access and refresh tokens stay in this browser's site storage until you disconnect or clear site data.

**Who's watching?** follows Nuvio Mobile's launch rules. It appears after signing in (unless the account has a single profile without a PIN) and, by default, on every new visit; refreshing the same tab keeps an unlocked profile. **Settings → Accounts and profiles → When you open the app → Remember last profile** opens straight into the last profile instead, like Nuvio's *Remember Last Profile*. A PIN-protected profile always asks for its 4-digit PIN, including after a refresh: the unlock is held in memory only and Nuvio verifies the PIN before the profile is entered. Rate-limited attempts disable the keypad until Nuvio allows another try. A refreshed title or player link reopens after its profile is chosen. A profile that gained a PIN or was deleted on another device brings the picker back with the reason. Profile names, colours and lock states are cached for the picker. Avatars show the profile's Nuvio colour and initial; avatar images are not fetched. Create, edit or lock profiles in the Nuvio app. If the account has no profiles, create a primary profile here or in Nuvio Mobile; if the profile request fails, use **Retry** to try again. The app imports addons, enabled plugin repositories, library titles, and watch progress on sign-in and every 10 minutes. Disabled addons remain visible in Manage addons. The Nuvio **Sync now** button refreshes them immediately. Imported sources are combined with local and Stremio sources for browsing. Browser CORS and scraper runtime limitations still apply.

Nuvio Continue Watching includes unfinished titles outside the library and **Next up** after a completed episode. Watched history from the selected profile also contributes, including episodes marked watched in Nuvio. Episodes count as complete at 90%; tiny positive progress still appears as **<1% watched**. A newer partial episode resumes; otherwise the next available episode opens at position zero. A new season needs a known past release date. Episode metadata resolves in the background for up to 16 recent title candidates with two lookups at a time. See [Nuvio feature gaps](NUVIO_FEATURE_GAPS.md) for remaining integration differences.

Use the **•••** button on a Continue Watching card for watching controls. Nuvio movies and episodes support **Mark watched / Mark unwatched**, and episode details include watched badges and **Mark season watched / unwatched**. Unwatched clears that episode's progress and watched marker. **Hide from Continue Watching** keeps progress/history and hides the title until newer watching activity. **Reset playback progress** clears resume positions for the title in connected accounts while preserving watched history; a series can still have Next up. Nuvio dismissals sync in Streams' own profile-settings namespace; native Nuvio dismissal preferences are separate. Stremio-only dismissals stay in this browser.

Nuvio progress and watched history use persisted delta cursors after an initial full snapshot, checking every 30 seconds while the page is visible and when it becomes visible or reconnects. These reads are independent of TV callbacks: a TV must still upload its own progress before Streams can receive it. Unsupported or expired delta APIs fall back to full pulls, with periodic background full refreshes on older backends. Addons, plugins and library still refresh every ten minutes.

Playback changes are queued in browser storage before sending them to the cloud. Playback positions persist at most every five seconds while playing and immediately on pause, stop, completion, or leaving the page; routine cloud writes are limited to once per 30 seconds per item, with final states sent immediately. Failed saves survive reload and retry on reconnect, return to the page, and periodic checks. **Accounts → Retry saves** retries queued changes. Account/profile scopes stay separate; reopening imports cloud changes first and discards older queued progress if newer cloud progress exists. Disconnecting an account discards its queued changes. Closing the browser stops retries until you reopen it, and clearing site storage removes unsent changes. Provider clips shorter than 121 seconds are excluded from movie/series progress saves to avoid treating error clips as watched episodes.

While signed in to Nuvio, addons and plugin repositories installed under **Settings → Addons** are saved to the current profile. Source removals and Nuvio library changes also sync back. Profiles configured to share the primary profile's sources must be edited from the primary profile. Browser playback and linked TV movie and episode casts report watch progress to the connected account. Direct movie casts on older PlayBridge versions do not provide playback callbacks.

### Scraper controls and configuration sync

Under **Settings → Addons → Plugins**, individual scraper On/Off switches for a **Nuvio profile** repository now save to that profile. Scrapers declaring `hasSettings` have a **Configure** button that loads their `onSettings()` layout in an isolated worker. Text, masked password/token, select, toggle, and number fields are supported. Saved values are passed to the scraper as `SCRAPER_SETTINGS`; its ID is available as `SCRAPER_ID`. Configuration changes use a different stream-cache key, so the next lookup uses the new settings immediately.

These preferences sync between **Bridged Streams devices using the same Nuvio account/profile**, on restoration, every 10 minutes, or with **Sync Nuvio now**. Repositories marked **This browser** keep their switches and configuration local. Shared plugins use the primary profile's preferences and must be edited there. Failed saves leave the previous value intact and can be retried.

The inspected Nuvio Mobile version syncs repository URLs but stores individual scraper switches and settings only on the device. Bridged Streams cannot import those device-local values or change them in Nuvio Mobile. It uses Nuvio's existing `sync_pull_profile_settings_blob` / `sync_push_profile_settings_blob` APIs with its own `bridged-streams` platform namespace. Native mobile and TV settings are not overwritten. Each write reads the latest snapshot and merges only the scraper being changed; newer backends use the guarded RPC with conflict retries. Older backends fall back to the original RPC and simultaneous cross-device saves may use the last write. A backend missing the settings RPC reports a sync/save error rather than claiming success.

Plugin settings, including user-entered tokens, are stored in this browser's site data and in the selected Nuvio profile. The settings object is supplied to that scraper's worker. Any stream URLs or headers produced by the scraper follow the normal playback and casting flow.

## Addon controls

**Settings → Addons** shows only the sources of the account in use: the current Nuvio profile's addons and plugin repositories, the Stremio account's addons (Stremio has no plugin repositories), or, when signed out, the addons and plugin repositories saved in this browser. Installing adds to that same place. Sources saved in this browser are not used while signed in and return after signing out; the panel offers to add them to the account (plugin repositories only to a Nuvio profile), remove them, or keep them for signed-out use. Device plugins on Android belong to the device and are listed under **Plugins** for every account. Catalog refresh and cache controls sit at the bottom of the Addons list. **Settings → Playback** holds the device-wide stream choice, player and diagnostics settings.

Catalogs may use the addon's own content types (for example `Tube`, `JAV` or `Live`) besides movie, series and sport. Their rows load on Home, titles open in details with shareable links such as `/#/Tube/<id>`, and streams come from addons that declare that type; Nuvio scrapers apply only to movies and series. Types named like app routes (`catalog`, `home`, `search`, `settings`) are skipped.

Open **Settings → Addons** to change addon priority, turn an addon on or off, refresh its manifest, copy or open its URL, and remove it. Addons with a configuration page have a **Configure** link. The feature button lets you turn catalog, metadata, stream, and subtitle resources on or off separately. Catalog, metadata, and stream switches affect the website's requests; subtitle lookup is not yet part of browser playback.

Local addon order and switches stay in this browser. Stremio addon order syncs to Stremio, while its on/off and feature switches stay in this browser. Nuvio addon order and the main on/off switch sync to the selected Nuvio profile; per-resource switches stay in this browser. Disabled or unreachable addons remain listed so you can refresh, re-enable, or remove them. Cached addon manifests, catalog rows, and library data let the page show familiar content immediately after a refresh while account and addon requests update it in the background. Nuvio Home shows its cached rows before profile validation when the same backend, user and profile passed a profile check in the last 24 hours without a PIN, a refresh token is saved, and the cached rows are less than 24 hours old. An expired access token doesn't prevent this; validation refreshes it first. Protected profiles, other users' caches and unknown or old caches wait for validation or unlock. Cached display never grants write or PIN authority. Validation starts immediately: failed online validation hides the cached rows; offline, they stay only until the 24-hour authorization expires, and reconnecting revalidates. A revoked session signs out, and a profile that gained a PIN or was deleted erases its cached rows and fences pending work. A deleted profile requires an explicit choice. Nuvio catalog cache keys include account and profile identity; profile switches clear shared title and catalog display caches, and title previews are cleared at startup when the saved profile is known to have a PIN. A successful unchanged validation preserves details, search and scroll. A device can't learn about a PIN or revocation added elsewhere until its validation response arrives, typically within a second of opening. Nuvio data from a PIN-protected profile stays hidden until that profile is unlocked. Stream URLs are resolved when you choose a title or episode. You can refresh catalogs manually, choose a 15, 30, or 60 minute auto refresh interval, or clear cached rows.

## TMDB enrichment

Open **Settings → Integrations → TMDB enrichment** and enable it with your own TMDB API key. It is off by default, uses the same browser-stored key as Nuvio scraper lookups, and does not require a TMDB account login in Bridged Streams. Choose a preferred language and independently enable artwork, basic information, title details, cast and crew, production companies, networks, episode details, season posters, trailers, recommendations, and movie collections.

Metadata providers run concurrently: a ready fallback waits up to 300 ms for higher-priority sources, and each lookup has an eight-second deadline. Higher-priority same-title results can upgrade the detail while it remains open. Leaving the title cancels the lookup. Known preview artwork stays visible during loading and optional enrichment.

Addon details appear first; TMDB enrichment loads in the background without delaying Play or stream selection. Public metadata is cached in this tab for six hours, with at most 60 cached API responses. Failed requests are not cached and can be retried. Episode details are fetched only for the season being viewed. Addon title IDs, episode IDs, release dates, existing IMDb ratings, and progress identity are preserved. TMDB fallback ratings are labeled TMDB. Trailers with missing or broken thumbnails are hidden; if none remain, the trailer row disappears. Failed title logos fall back to plain-text titles. Visible trailers open in a responsive YouTube embed popup inside the app, with fullscreen controls and an optional YouTube link. Closing the popup or navigating away removes the player and stops playback. Recommended and collection titles use their IMDb identity for compatible addons when TMDB supplies one; playback still depends on installed stream providers, and series need an addon episode list.

Bridged Streams requires a user-entered key. Enrichment preferences are local to this browser and are not synced to Nuvio profiles.

## Casting

### Automatic stream selection

Open **Settings → Playback → Stream selection mode**. **Manual** (the default) leaves the stream list open; **First stream** uses provider order; **Regular expression** matches provider/name/title/description/URL case-insensitively; **Preferences** requires the chosen resolution and release types and prefers the chosen provider. The regex editor includes 13 presets, validation, and a match count for the last loaded stream list. Filters appear in Preferences mode; their saved values also drive **Sort streams by preference**, independently of mode. Sorting retains every result and preserves ties.

Play, Resume, and choosing an episode use these settings with the selected playback destination. With automatic selection on, a full-screen opening dialog covers the detail with artwork, title/episode, status, **Cancel**, and **Choose manually**. The stream list does not render during successful automatic selection. Cancel, Escape, or Back cancels the attempt and stays on detail. Browser playback replaces the transient opening history entry, so Back returns to detail; **Choose another stream** explicitly opens the manual list. Native playback keeps the detail visible after dispatch. The primary action shows Play or the exact Resume episode and position; **Choose stream** opens the manual list directly. Manual mode retains its existing flow.

**Prefetch streams on detail** defaults On and runs only when automatic selection is effective. After 300 ms on a detail, it prepares the exact movie/episode that the primary button would play. Play adopts that lookup, including in-flight results, for up to the existing five-minute stream-cache window. Moving away cancels an unadopted lookup, terminates browser workers, and cancels native resolution. At most four source jobs run concurrently. Prefetch never starts playback. Selection timeouts start at the tap, not at prefetch; completed results decide immediately. Up to three unique ready candidates are ranked by remembered link, binge group, then selection mode. An initial browser load error or rejected native load tries the next candidate; playback errors after the first browser `playing` event never switch sources. Native success is the host's accepted playback session; a rejected promise is retryable, while destination/permission errors return to manual choice.

Continue Watching opens details and starts the same resume-episode prefetch by default. **Resume directly from Continue Watching** defaults Off; when On with automatic selection, tapping a card immediately opens the resume attempt. Its **••• → View details** action remains available.

Instant selects from results as they arrive. A bounded timeout (3 seconds by default) selects when eligible sources finish or its deadline arrives; a ready preferred provider can start once no pending provider can outrank it. Unlimited always waits for all eligible providers, with a hard 60-second limit that returns to manual selection. **Finding a stream… → Choose manually** opens the manual list for this visit. No match or timeout opens the list with an explanation. **Play/Resume best match** makes an explicit new attempt. Back, refresh, and shared stream/player links stay manual.

Source scope and optional allow lists apply before selection, including next episodes. Empty allow lists mean all sources of that kind; unavailable saved entries remain removable. Add-ons use their manifest URL. Browser and native plugin scrapers share the stable ID `${repository.manifestUrl}:${scraper.id}`; selection uses trusted source metadata rather than provider-returned names or URLs. Settings migrate from the v1 Auto-select switch to v2 modes without losing filters or sorting.

**Reuse last link** stores only a fingerprint (provider URL, sanitized name/title/group, SHA-256 of the media URL) and timestamp, never the media URL or headers. Each revisit adopts a current lookup or fetches sources and prefers an exact fingerprint match within the chosen duration (24 hours by default). Changed signed media URLs do not match. **Reuse binge group** remembers a series' last played group for Play/Resume. Both stores are limited to 100 entries each, retain only the current account/profile, and clear on sign-out or profile change. Settings themselves stay device-wide. Browser reuse records the player's `playing` event; native playback records an accepted session and later playing progress for queued episodes.

**Auto-play next episode** defaults On to preserve Streams' existing behavior (Nuvio Mobile defaults Off). **Prefer binge group** tries the current group, then the existing provider/name/quality continuation before mode rules. With continuation fallback On, the mode chooses the next stream; Manual uses the first eligible stream. With fallback Off and no continuation, the browser opens the next episode's stream list and TV supply intentionally stops. Disabling next-episode auto-play leaves browser playback ended and supplies no further TV items. Settings are captured for the playback session. Failed or empty TV lookups remain retryable, including partial batches. Cast resolution remains lazy.

These options follow the local Nuvio Mobile reference with Streams-specific preference filtering, source IDs, fingerprint-only reuse, the On next-episode default, and strict wait-all Unlimited semantics. Nuvio's threshold prompt and optional Mobile-settings import are not implemented; no native settings blob is written.

- Choose **Play** on a stream to watch in the website with MoviPlayer. It is loaded only when playback starts and supports MKV, MP4, HLS, DASH, and other formats supported by the player. Its FFmpeg WebAssembly engine is served as a separate, versioned `.wasm` asset. Deploy the entire `dist` directory so that asset is available. The source must allow browser requests, including media segments and required headers. A native video fallback is used if MoviPlayer cannot load.
- With a supported PlayBridge playback bridge, **Settings → Playback → Use PlayBridge video player on this device** chooses the built-in phone player (On by default) or Streams’ browser player for **This device** only. Remote destinations and Cast stay unchanged. **Player opening orientation** defaults to **Landscape**, with Portrait and Automatic choices, and applies only to supported native local playback. Both preferences stay in this browser, outside account/profile sync. Older hosts explain that an update is needed for orientation; browsers without a playback bridge keep the web player.
- **Settings → Playback → Native player fallback** controls whether the browser's video player is tried when MoviPlayer cannot play or load. It is on by default and saved in this browser.
- If playback fails, open **Playback diagnostics** below the error, run **Check player engine**, and copy the report. The same report is available under **Settings → Playback** after closing the player or refreshing the page. It records recent import and playback events, asset timing, browser capabilities, and a direct WASM fetch and compile check. Stream URLs, request headers, and account credentials are excluded. Use **Clear history** to remove the saved entries.
- **Addon subtitles** in the browser player queries enabled subtitle resources for the current movie/episode. Choose a provider/language to fetch and render a VTT or SRT track; **Off** removes it. Tracks reset when the episode changes. Subtitle requests must support browser CORS. Provider markup renders as plain text; file size and request time are bounded. Embedded player tracks remain available in MoviPlayer. Addon tracks currently apply to browser playback; external subtitle casting and automatic language/matching preferences are separate work.
- Browser movie and episode resumes seek to the saved position without reloading the source. Queued or failed seeks remain unconfirmed until playback reaches that position; startup progress cannot overwrite the saved time before then. This applies to MoviPlayer, its internal native-video handoff when browser fetch cannot read a source, and the separate video fallback after a failed Movi import. The internal handoff relays readiness, seek, pause and progress events without duplicating EOF. Each new episode has independent player/resume state. Browser playback reports movie and TV watch progress to connected accounts. TV playback looks for the next episode from the same source when the current episode ends.
- Movies use `window.playbridge.linkCast()` with one item when available so watch progress can sync. Older PlayBridge versions fall back to `cast()`.
- Series use `window.playbridge.play()` for the selected native destination (or legacy `linkCast()`) with the chosen first episode. Further episode streams resolve only after a `needitems` event and are supplied through `provideItems()`. Empty/failed lookups leave the demand open for a fresh retry rather than declaring the series finished; partial batches keep the queue open. Local Android/iOS players expose the live queue and next/previous controls in updated PlayBridge builds. The owning app page must remain loaded for further resolution.
- **Cast** is an additional action shown for each stream when the PlayBridge bridge is available. Linked casting needs a PlayBridge version with `capabilities.linkedCast`.
- Streams requiring a torrent engine, local debrid resolution, or proxy headers are shown as unavailable for direct casting.

## Browser plugin support

Nuvio plugin code runs in a Web Worker with browser APIs and a 30-second timeout. Like Nuvio, `require` supports `cheerio` (including `cheerio-without-node-native` and `react-native-cheerio`) and `crypto-js`. The `cheerio` and `CryptoJS` globals are also available. `global`, `window`, and `self` refer to the isolated worker runtime, without access to the app DOM or local storage. CommonJS exports and top-level/global `getStreams` functions are supported. Unsupported modules report their name instead of a generic `require is not defined` error.

Browser CORS rules still apply to the repository, scraper code, and sites a scraper fetches. Native-only Nuvio host functions (native fetch, DOM/WASM bridges, debrid services) and other Node modules are unavailable. Scrapers that declare only native platforms are skipped. Use plugin repositories you trust; their code runs locally after installation.

Plugin playback headers are normalized before stream eligibility checks. Client-controlled headers such as `Connection`, `Accept-Encoding`, and `Sec-Fetch-*` are removed so otherwise usable results (including Castle) are not hidden. Supported provider headers, including User-Agent, Referer, Origin, cookies, and authorization, are preserved for playback/casting. Unsupported application headers still prevent eligibility; normalization does not bypass the cast header policy. Successfully fetching a stream does not guarantee its media host permits browser playback.

For IMDb-based catalog IDs, enter your own TMDB API key in Addons. The key stays in this browser's local storage and is sent to TMDB for ID lookup and to the selected scraper worker. Manifest URLs and plugin repository URLs also stay in local storage. Clear site data to remove them.

## Device plugins (PlayBridge Android)

Android FOSS builds offer an optional device resolver, off by default. Play Store builds exclude the native plugin runtime; iOS has no native resolver. When running on a supported PlayBridge Android host (`window.playbridge.capabilities.nativePlugins === 1`), installed native providers can resolve streams using the Android engine without sending JavaScript scraper code, HTTP URLs to fetch, plugin settings, or account secrets across the bridge.

- Choose **Manage device plugins** in Addons to open the shared native Android addon settings. Library uses the same manager while it remains available. Approve installed code and requested provider domains there before resolving streams. Changed code waits for explicit update approval.
- Scraper resolution prefers the native engine for installed device providers. If native resolution fails, is unapproved, or disabled, it does not fall back to executing web worker scraper code.
- Device providers are recognized as stream sources even if the web plugin repository list is empty. When both web and device repository entries exist, both applicable enabled toggles are respected without duplicate stream sources.
- Stream headers returned by native providers are normalized before stream eligibility checks to strip client-controlled headers (`Connection`, `Accept-Encoding`, `Sec-Fetch-*`) while preserving provider requirements (`User-Agent`, `Referer`, `Authorization`).
